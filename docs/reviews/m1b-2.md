# M1b part 2 review — resolutions

Picky review (P) and security review (S) of M1b part 2, the words engine (`m1b-words-engine`),
round 1, with the owner's decision on each. One line per finding: ID → outcome (where). Neither
review found a blocker; the picky reviewer's independent fuzz (390k plays against its own rules
model) found no mismatch. Spec changes stay in v0.9.10 (README history line).

## Picky review (P)

| ID | Outcome | Where |
|---|---|---|
| P-1 | Fixed (owner decision): the ruleset schema caps `maxPlayers` at 2 until multi-player resignation is specified; `leave()` throws for a game of more seats (a precondition, 02 §2.1 rule 3); words §8.2 and §10.6 reworded; tests for both | `rulesets/schema.ts`, `state.ts`, words §8.2, §10.6 |
| P-2 | Fixed: after every transition the property tests also check that every run of two or more tiles is a dictionary word, the tiles are connected through the start square, each seat's score is its plays' record scores plus its final adjustment, and `out` adjustments sum to 0; a test shows the checks catch each kind of bad state | `engine/property.test.ts` |
| P-3 | Fixed: transition scores come from a hand oracle in the test (the ruleset's own premium picture and tile table, independent of the engine's scoring code), not from `preview` or `lastMove`; the `≥ 4` check is gone. Kept layout-agnostic rather than hard-coding today's numbers (AT = 4, CATS = 6), because issue #10 may move premiums: the oracle gives those numbers on today's layout and follows any future one; classic's double-word start square, which the spec fixes, is asserted directly, and the casual opening is scored too | `engine/state.test.ts` |
| P-4 | Fixed: `recordSchema` is a discriminated union on `type`: a play requires 1+ placements, 1+ words and `bingo`; a swap requires `swapCount ≥ 1`; the rest score 0 without a bingo.
