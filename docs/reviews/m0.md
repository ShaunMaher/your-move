## Round 2: pipeline 81916 (CI)

| ID | Outcome | Where |
|---|---|---|
| CI-1 | Round 2's diagnosis was incomplete: the `-slim` image's missing CA certificates do stop workerd (reproduced, and fixed by the full image), but pipeline 82026 still failed on the full image. The remaining cause is the runner's CPU: workerd's linux-64 build needs SSE4.2 (x86-64-v2), and the amd64 runner's VM uses the generic `qemu64` model without it. Reproduced under KVM: on `qemu64`, and on `qemu64` with SSSE3, SSE4.1 or POPCNT added, workerd fails at isolate bootstrap with the same empty `jsg.Error` ("per-isolate bootstrap: unknown script"); with `+sse4.2` alone, or `host`, it serves. Open: needs a runner CPU type with SSE4.2 (owner) or the Worker tests on another runner; the test now names the cause, and the job prints the CPU when it fails | 6b1c7e3, 5ad64f1, d80ed5d |
| CI-2 | Fixed, same cause: osv-scanner verifies TLS with the system certificates. The full Node image is pinned by digest and needs no `apt-get`; the server image stays slim, because Node verifies TLS with its bundled roots (so the Gmail API calls in M4 work there) | 6b1c7e3 |

## Local Docker evidence (P-16)

Built and run on an amd64 workstation at `f413b68` (round 1) and again at 221b60a (round 2);
arm64 is built only by CI.

- `docker build -f apps/node/Dockerfile .` succeeds: pnpm installed through mise at the
  `mise.lock` checksum, `games:verify --fast`, web and server builds, `pnpm deploy --prod`.
- `docker run --read-only` with a production-like configuration (https `PUBLIC_URL`, `smtp`):
  `GET /api/health` → `200 {"ok":true}` with the 08 §3 headers including HSTS; `GET /` → the shell
  with `Cache-Control: no-cache`; the process runs as `node` (uid 1000); the container health
  check reports `healthy`.
- Labels: `org.opencontainers.image.revision`, `.title`, `.licenses` and
  `com.gitlab.ci.pipeline.id`/`.url` as passed at build time.
- Started with plain `node dist/main.js` (no `--disallow-code-generation-from-strings`), the
  server refuses: "Refusing to start: run node with --disallow-code-generation-from-strings",
  exit 1.
- The CI image path, run locally: the kaniko fork's debug image builds the same Dockerfile
  unprivileged in about two minutes (`--snapshot-mode=redo`), writes the tarball, and
  `scripts/ci/install-syft.sh` + syft write a CycloneDX SBOM from it.
- Round 2, the image job's script as CI runs it on `main`: kaniko with `--cleanup` builds the
  image and writes the tarball; afterwards the job container has busybox only (no `node`, no
  `/bin`), and `sh scripts/ci/install-syft.sh` + syft write the image's CycloneDX SBOM.
- Round 2, the image at 221b60a: read-only run healthy as uid 1000, `GET /api/health` 200 with
  HSTS and `no-store`, `GET /` with `no-cache`, labels carry the commit and pipeline id, and the
  server still refuses to start without the code-generation flag.
