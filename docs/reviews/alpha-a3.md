# Alpha slice A3 review — resolutions

This record covers round 1 of the review of alpha slice A3, the words board UI (`alpha-a3-words-ui`):
the picky review (P) and the security review (S). Each line gives the finding's ID, its outcome and
where the fix lives. The spec changes are in v0.9.17 (the README history line; the owner renumbers
at merge).

## Picky review (P)

## Security review (S)

| ID | Outcome | Where |
|---|---|---|
| A3-S-1 | Fixed (owner decision). A module may use `localStorage` only under the reserved prefix `ym.game.<gameType>.<userId>.<gameId>`, which the shell wipes (every key starting `ym.game.`) at sign-out and logout-all; 02 §3, 06 §4 and 07 §2 say so. The board stores only the permutation (positions in the sorted rack), never letters; writes only after the player reorders (shuffle, or a drag or return that changes the order), never on mount; ignores a saved value that isn't a permutation of this rack; and deletes the entry when the game isn't active. The user id comes from the envelope (`players` row of `yourSeat`); without one nothing is stored. Tests: nothing on mount or after a tentative placement, the key and the format, a drag reorder, a finished game clears the entry, another account's entry and a wrong-size entry are ignored, storage that throws. **For slices A1 and A4:** the wipe itself belongs to the shell (sign-out and logout-all remove every `localStorage` key starting `ym.game.`); this slice only keeps to the rule. | `storage.ts`, `Board.tsx`, 02 §3, 06 §4, 07 §2 |
| A3-S-2 | Deferred to the AI milestone: the alpha has no AI seats (roadmap, Alpha section). `seatNames`' doc comment says that every seat is shown by display name alone and points to 08 T31 for the label that must come with AI seats. | `text.ts` |
| A3-S-3 | Fixed. Preview answers are cached by game version and tiles (a bounded map), so the same tiles aren't asked twice. Play is disabled only for `INVALID_WORDS` and `INVALID_PLACEMENT`; `RATE_LIMITED`, `STALE_GAME`, other errors and network failures count as "couldn't check" (Play stays enabled, nothing is cached, so a later attempt asks again). The debounce is 250 ms, and 600 ms when a game resource is a `serverOnly` list, since each check there is a request. Tests for each error class, the cache, the retry and the longer delay. | `Board.tsx`, `Board.test.tsx` |
| A3-S-4 | Fixed with P-1. | see P-1 |
| A3-S-5 | Fixed in part; corrected in round 2 (A3-P2-6). The words package is two TypeScript projects: `tsconfig.engine.json` (the engine, manifest and kit tests; lib ES2023 and no DOM) and `tsconfig.client.json` (the client, with the DOM, referencing the engine's build). A use of `window` or `document` in `src/engine` is a type error as well as a lint finding. The Node types the engine project loads (for its tests) also declare `crypto`, `fetch` and `process`, so those are not caught by the type check; the engine lint allow-list and the architecture rules cover them, unchanged. | `games/words/tsconfig*.json`, `package.json` |
| A3-S-6 | Fixed. `webCryptoRandom.nextInt` calls the SDK's `assertRange` (an integer from 1 to 2^32). Test. | `random.ts`, `random.test.ts` |

## Round 2

Findings of the second review of the same slice. The spec is unchanged in round 2.

| ID | Outcome | Where |
|---|---|---|
| A3-P2-1 | Fixed. A premium label now sits on a solid chip (`.ym-w-face`, padded, in the square's base colour), and the stripes show around it, so the label's contrast is the chip's: `dw-ink` on `dw-bg` and `tw-ink` on `tw-bg`, which the existing pairs already measure, are now what is rendered. A test requires a chip rule for each premium. Word squares stay distinguishable by the stripes and the label. | `styles.ts`, `styles.test.ts` |
| A3-P2-2 | Fixed. `styles.test.ts` parses the sheet and fails if a `color` or `font*` declaration for a `.ym-w-sq` or `.ym-w-tile` selector has lower specificity than `.ym-w button`, or ties and comes earlier. A second test feeds it a sheet with the old bug and checks that it is caught; a third pins the specificity arithmetic. | `styles.test.ts` |
| A3-P2-3 | Fixed, with one deviation. The placed-tile ring is now a light amber (`ring`) inside the tile, and the last-play notch light amber (`notch`); on a blank tile both use the accent colour. The focus ring on a square is a two-band ring (accent outside, light inside, also inside a tile) so it reads on a navy tile and on an empty square. The pairs now describe what is drawn: `ring/tile`, `notch/tile` and `accent/blank-tile` at 3:1. The suggested `accent/tile` pair is not added: the accent colour is no longer drawn on a navy tile (the selected tile's outline sits outside the tile, on the rack or the square, which `accent/line` and `accent/cell` cover). | `styles.ts`, `styles.test.ts` |
| A3-P2-4 | Fixed. `client/index.test.ts` pins `client.versions` to `[1]` (a new rules version means editing it) and compares it with the engines' keys. `engineFor` no longer casts: it reads the table as `Readonly<Record<number, Engine>>`, with `Engine` the union of the table's values. | `Board.tsx`, `index.test.ts` |
| A3-P2-5 | Fixed. The preview tests use fake timers and no real sleeps: nothing at 249 ms and one question at 250 ms; nothing at 599 ms and one at 600 ms for a server-only list; the wait restarts when the tiles change; a taken-back and replaced play is not asked twice. The "shrug" test is retitled to what it checks. New test: a valid answer cached for one version is not shown after a version change, and Play waits for, and then obeys, the new refusal. | `Board.test.tsx` |
| A3-P2-6 / A3-S2-1 | Fixed (comment and record). The comment in `tsconfig.engine.json` and the A3-S-5 row above now say what the check does: DOM globals (`window`, `document`) are type errors; Node-provided globals (`crypto`, `fetch`, `process`) stay with the engine lint allow-list and the architecture rules. Splitting the Node-dependent tests out so the engine compiles with `"types": []` was not done: the kit and dictionary tests live beside the engine sources and the split is not small. The long round 1 commit subject stays as history. | `tsconfig.engine.json`, this file |
| A3-S2-2 | Recorded as input to M6, no code now. When the shell's `preview` fails with `RATE_LIMITED`, a server-checked preview should back off (honouring `Retry-After`) rather than asking again on the next change; today the board only treats it as "couldn't check" and caches nothing (A3-S-3), so a later edit asks again after the debounce. | M6 (rate limits) |
