# 09 — Operations

## 1. Configuration

All configuration comes from environment variables (Node) or vars/secrets (Cloudflare), parsed and
validated by one Zod schema at startup. Invalid config → refuse to start with a clear message.
`.env.example` documents every variable.

### 1.1 Secret derivation and rotation

Subkeys are derived from `APP_SECRET` with HKDF-SHA256, each with a distinct, versioned `info`
label:

| Label | Used for | Effect of changing it |
|---|---|---|
| `otp/v1` | OTP code hashing | live codes stop working (≤ 10 min impact) |
| `ip/v1` | IP-bucket hashing in rate limits and audit events | rate-limit counters reset; audit correlation breaks |
| `unsub/v1` | unsubscribe token MAC | old unsubscribe links stop working — **avoid**; if rotated, keep verifying `v1` too |
| `email-id/v1` | `emailId` = HMAC of normalised email: suppression list, per-target invite limits, log identifiers | **suppression list silently empties** → previously unsubscribed/bounced addresses get mailed again. Never rotate this subkey without re-keying the table. |

Rotation procedure (documented in `docs/deploy.md`): introduce `APP_SECRET_PREVIOUS`; derive `v1`
keys from the previous secret for verification of `unsub` and for `email-id` lookups while a
one-off job re-hashes `email_suppressions` (and new `v2` labels are used for writes). Until that job
exists, **rotating `APP_SECRET` is unsupported** and the docs say so.

## 2. Email delivery

Email is critical (no email = no sign-in). The `EmailSender` interface has HTTP-API implementations
that work on both runtimes, plus SMTP for Node only.

- Recommended: a transactional provider with an HTTP API (Resend, Postmark, Amazon SES). Cloudflare's
  own Email Service is supported via its `send_email` binding *if* it's available on the operator's
  account (Email Routing's older `send_email` binding only sends to verified addresses and is NOT
  suitable).
- The sending domain MUST have SPF, DKIM and DMARC configured; document this in `docs/deploy.md`.
- Every non-OTP email carries `List-Unsubscribe` and `List-Unsubscribe-Post` headers.
- Templates: plain-text + minimal HTML, no remote images, no tracking pixels, no link tracking.
- Bounce/complaint webhooks (provider-specific) feed `email_suppressions` — nice-to-have in v1.
- Dev: `console` provider plus a `/__dev/emails` page listing captured emails so Playwright can read
  OTPs. Both are available only when `isLocalDev(config)` is true (06 §4) — a runtime check, not
  just a build flag — and the CI suite asserts `/__dev/emails` is 404 in a production-config build.

## 3. Cloudflare deployment

- Worker with: Static Assets (built SPA), D1 binding `DB`, Durable Object binding `USER_CHANNEL`
  (SQLite-backed DO class, declared in migrations), Cron Trigger `*/15 * * * *`.
- `apps/worker/wrangler.example.toml` is committed with no account-specific IDs; operators copy it to
  `wrangler.toml` (git-ignored) or pass `--config`. CI generates its config from non-secret CI
  variables (D1 database id, route/custom domain).
- The example sets `workers_dev = false` and `preview_urls = false` (with a comment: enable
  `workers_dev` only while testing without a custom domain), so the app isn't served on extra
  origins.
- Smart Placement enabled (03 §11).
- R2 bucket binding `BLOBS` for `BlobStore` (uploaded/operator dictionaries). Private bucket, no
  public access, no `r2.dev` URL.
- Commands: `pnpm cf:migrate` (D1 migrations), `pnpm cf:deploy`, `wrangler secret put APP_SECRET` etc.
- Target: fits the Workers Free plan for small groups of friends (10 ms CPU/request — which is why
  dictionary lookup must not parse per request, 03 §10). The Paid plan ($5/mo) lifts CPU and
  request limits. Record measured CPU per endpoint and free-tier headroom after M3.

## 4. Docker deployment

- Multi-stage `apps/node/Dockerfile`: build with pnpm, runtime on a slim Node LTS image pinned by
  digest; runs as non-root UID; read-only root filesystem except `/data`; `EXPOSE 8080`;
  `HEALTHCHECK` on `/api/health`.
- Migrations run automatically on start (with a lock).
- `docker-compose.example.yml`: app + Caddy (automatic HTTPS) as reverse proxy, named volumes for
  `/data` and (separately) `/data/blobs`, `TRUST_PROXY=true`.
- Image name and labels come from build args — no product name baked in.
- Backups: documented options — nightly `sqlite3 /data/app.sqlite ".backup ..."` sidecar, or
  Litestream to S3-compatible storage. Recommended retention 30 days (deleted accounts disappear from
  backups within that window; stated on the privacy page). Cloudflare: D1 Time Travel (30 days on
  paid plans) — same statement.
- Compose: the app container is on an internal-only network and its port is **not** published to the
  host; only Caddy is exposed (otherwise `X-Forwarded-For` could be spoofed by connecting directly).
- Single instance only (see 03 §5.3).

## 5. Observability

- Structured JSON logs (`level`, `msg`, `requestId`, `route`, `status`, `durationMs`, `userId`
  where relevant). `route` is the route **pattern** (`/api/games/:id`), never the raw path. Never
  log OTPs, tokens, cookies, request bodies, emails in any form other than the HMAC `emailId`, or
  game secrets.
- Validation and module errors are logged by code and path only, never with input values
  (e.g. strip Zod's `received`). Unhandled exceptions log the error class, message and stack, and
  the client gets `500 INTERNAL` with no detail (05 §Errors).
- Cloudflare: Workers Logs (retention per Cloudflare plan). Docker: stdout (operator's log
  retention). The privacy page states both.
- No third-party error tracking by default. A `/api/health` endpoint for uptime checks.

## 6. CI (GitLab)

`.gitlab-ci.yml` stages: `install` (`--frozen-lockfile`) → `lint` + `typecheck` → `test` (unit +
integration on both DB drivers) → `build` (web, worker, node) → `e2e` (Playwright, WebKit +
Chromium) → `docker` (build image; push to GitLab registry on default branch) → `deploy` (manual
job, `production` environment, default branch/tags only: `wrangler d1 migrations apply` then
`wrangler deploy`, from the build artifact without re-installing; credentials per 08 §6). Also
`pnpm audit --prod` and a licence check that all runtime dependencies are permissively licensed
(BSD/MIT/Apache/ISC/0BSD/public domain). CI images pinned by digest.
